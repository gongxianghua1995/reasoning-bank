- 原生 mini-swe-agent 1.10.0 单 agent Bash ReAct，加 ReasoningBank 逐题记忆；不启用 MaTTS、多角色协作或多候选选择。
- DeepSeek-V4-Flash-0731；解题 temperature 0.2、max_tokens 16384、250 步、1200 秒；自评 temperature 0、提炼 1，各另有 180 秒预算。
- 历史 query 的 cosine top-1 检索；本地 BAAI/bge-small-en-v1.5（384 维、512 输入 token 截断）替代原版 Gemini embedding。这是方法实现差异，不是原论文分数复现。
- 空记忆起步，顺序固定为 10999 → 11141。宿主访问模型 API；解题、官方评分容器均断网。4 条实际容器网络记录全部为 `none`。

## 提炼故障、修复及补验

第二题原始提炼响应是一条继续跑测试的 Bash 动作，没有 `Memory Item`，严格解析因此失败。原始记忆保持只有第一题一条经历（3 个记忆条目），批次退出码为 1。

修复内容：

1. 保留原版成功/失败 system 提炼提示，将历史消息序列化为带角色的 JSON，明确其起止和数据性质；结尾重申当前任务是提炼记忆。
2. 提炼格式错误最多纠正一次，两次共用 180 秒阶段预算。保留各次正文、请求和格式错误事件；校验未通过不得创建记忆条目。
3. 汇总工具从独立 `self_judgment.json` 读取自评，避免提炼失败时误显示为无自评；增加请求数、空正文数和阶段错误字段。

6 项契约测试通过，包括错误 Bash 响应后恢复、持续错误时有界退出且不写条目。随后对第二题保存的轨迹进行独立真实提炼补验：沿用原 LLM 自评，仅额外调用 **1 次**，约 **18.8 秒**内提取 **3 条**经验并成功写入记忆副本，副本共 2 条经历。没有读取官方测试结果、重跑解题或覆盖原始实验记忆。

此次补验使用额外预算，属于单步修复验证；修复后的全新两题端到端批次尚未运行。
